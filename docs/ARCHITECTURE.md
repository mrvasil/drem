# Architecture

[← drem](../README.md)

## Два независимых состояния

Монитор определяет активность сессий. Контроллер сна решает, требуется ли
удержание. Иконка показывает состояние удержания, а счётчик показывает работу
агентов. Эти признаки нельзя объединять в один `isRunning`.

```text
Agent hooks ─────────────┐
Transcript file events ─┤
Codex goal DB events ───┤
Known PID exits ────────┤
15-second watchdog ─────┴─→ LiveActivityEngine ─→ AgentMonitor
                                                    ├─→ menu count and rows
                                                    └─→ KeepAwakeManager
                                                         ├─→ sleep assertions
                                                         ├─→ closed-lid override
                                                         ├─→ LidStateMonitor
                                                         │    ├─→ display brightness
                                                         │    └─→ AwayModeController → macOS lock screen
                                                         └─→ icon + preferences
```

## Сжатие контекста

`PreCompact` — рабочая фаза с действием «Сжимает контекст». Запись hook хранит
состояние продолжения: `auto` возвращается к работе, `manual` — к ожиданию ввода.
`PostCompact` либо `SessionStart(source: compact)` завершает только эту фазу.
Обычные startup/resume/clear по-прежнему начинают с простоя.

Пока есть `PreCompact` **той же сессии**, парсер не считает последующий
assistant `final_answer` / `end_turn` завершением пользовательской задачи:
это может быть итоговый текст summarizer. Явные `task_complete`, `turn_aborted`,
Stop/Interrupt/StopFailure и выход связанного PID продолжают завершать работу.
Hook timestamps сохраняют миллисекунды; старые записи без них читаются.
Дополнительного опроса, задержки выключения или нового владельца sleep assertions нет.

## Идентичность раньше эвристик

### Остров у выреза

`IslandController` владеет одним неактивирующимся NSPanel. Экран и геометрия
камеры берутся из NSScreen safe areas; экранные, lid и lock-события управляют
доступностью без опроса. Фокус остаётся в пользовательском приложении.
Прозрачная область анимационного окна пропускает мышь в нижележащее приложение.

`IslandEnvironmentSnapshot` читает состояние текущей CGSession, активного
встроенного дисплея и существующего IOKit-сервиса крышки при событии окружения
или команде показа. Неизвестная сессия/крышка запрещает показ. Sleep/lock-события
скрывают окно без анимационной задержки; уведомления не остаются единственным источником
неограниченно живущих флагов. После wake/Space/display-перехода есть одна
отменяемая перепроверка через 350 мс. Таймера опроса нет.
Явный Show пересоздаёт hosting view и повторно выставляет окно; `isVisible`
не принимается за доказательство присутствия в текущем Space. Отложенный callback
показа привязан к конкретному host и не действует после его замены или shutdown.
Повторные обновления скрытого состояния не переносят срок удаления host.
При активации приложения или смене Space панель не снимается во время перехода:
это исключает видимый blink. После единственной отложенной перепроверки drem читает
`kCGWindowIsOnscreen` у WindowServer и делает `orderOut`/`orderFront` только если
surface действительно отсутствует в активном Space. Уже composited-панель лишь
поднимается на свой уровень без пересоздания SwiftUI-модели и захвата фокуса.
Обработчики уведомлений переходят на следующий проход serial main queue,
сохраняя порядок sleep/wake. Нельзя обновлять модель синхронно из observer:
AppKit может отправить defaults-событие внутри раскладки текста SwiftUI,
и повторное создание host на том же стеке вызывает fatal access conflict.
Defaults-события фильтруются по экземпляру store острова: запись другого
компонента процесса не может снять временный display/lock/lid block.

`IslandLifecycle` — чистый автомат состояний. Скрытие привязано к полному циклу
работы, а не к session ID. Счётчик обновляется немедленно; текстовые строки
дедуплицируются по содержимому. После скрытия hosting view уничтожается вместе
с анимацией; остаются только обработчики клика/жеста возврата возле
камеры для возврата. Они отключаются вместе с доступностью острова.
`KeepAwakeManager` не зависит от острова, включая его завершающую анимацию.

`IslandSwipe` хранит захват и ось физического жеста, выдаёт непрерывную обратную
связь и фиксирует решение только при отпускании. SwiftUI рисует смещение/сжатие,
AppKit нормализует дельты и фазы; инерция не повторяет переход. Возврат создаёт
временный click-through compact host без сброса dismissed latch; отмена уничтожает
его после анимации. Для устройств без фаз есть один отменяемый debounce конца,
без polling. Прокрутка тела раскрытой панели не захватывается.

Его фактические `isActive`, `clamshellActive` и paused/agent-mode события отдельно
питают индикатор сна острова. Исчезнувшие рабочие сессии образуют ограниченную
четырьмя элементами визуальную сводку на 6 секунд, не рабочие записи детектора.
Стабильный FNV-хеш нормализованной папки выбирает seed персонажа; перемешанный seed
задаёт 24-битный токен пастельного цвета, один из семи силуэтов и небольшие черты лица.
Так параллельные агенты в одной папке разделяют один аватар, а разные папки не
сводятся к прежним семи цветовым корзинам. Provider, ID сессии и рабочий текст
на внешность не влияют. Имена сессий
поступают из структурированных локальных метаданных; не из prompt/summary.
Индекс Codex перечитывается только на старте/сверке и его файловом событии,
не на каждом обновлении transcript. Все поля исключены из диагностического CLI.

`IslandPresentation` хранит выбор по идентификатору сессии, а не по позиции.
Исчезновение выбранного агента возвращает обзор. Высота панели ограничена и
не растёт с количеством сессий. Один `IslandRobotView` переносится между
компактным и раскрытым состояниями; Core Animation двигает только его слои.
Малые blob-лица в сетке статичны. Мышь отслеживается событиями с квантованием,
не таймером. Reduce Motion и уничтожение host снимают повторяющиеся анимации.
Путь проекта приходит из уже привязанного процесса/сессии, без новых сканов.
Finder вызывается только явным кликом, только с локальным существующим каталогом.
См. [разбор движения и проверку](NOTCH-MOTION.md).

`AgentDetailParser` использует те же декодированные JSON-объекты, что и детектор.
Необязательный `AgentSessionActivity.detail` не участвует в классификации и
совместим со старыми сериализованными сессиями. Действия описываются только
по известным именам инструментов; публичный статус — явно последнее сообщение,
не утверждение о текущем прогрессе. Для Codex приоритет имеет явный короткий
заголовок из `response_item/reasoning.summary` или `item_completed/Reasoning.summary_text`;
тело summary и raw content отбрасываются. Это записанное событие, не подписка
на терминальный поток, поэтому заголовок может отставать от TUI.
Диагностический CLI исключает detail и рабочий путь.

`AgentAttentionParser` отдельно сводит подтверждённые вопросы по bounded ID и
времени; текст статуса не устанавливает и не сбрасывает ожидание. Claude
`AskUserQuestion` закрывается совпадающим результатом или новым подтверждённым
model-message с другим ID; соседние streaming-блоки не считаются продолжением.
`Notification/permission_prompt` в hook-state не меняет время активности и не
создаёт работу. Свежая подтверждённая работа или lifecycle снимает разрешение.
Объединение источников сравнивает времена ожидания отдельно от текстового статуса.
Idle/death и визуальные completion snapshots не сохраняют сигнал внимания.
Нативные журналы Codex не сохраняют pending input/approval events, поэтому live
ожидание Codex намеренно не определяется. Предварительный permission-hook не
доказывает, что запрос действительно ждёт пользователя.

### Привязка сессий

Сессия связывается с PID по открытому transcript-файлу или явному session ID.
Для обнаружения журнала остаётся резервное сопоставление по единственной
рабочей папке, только если у процесса нет более точной привязки. Hook не может
заимствовать чужой PID по совпадению cwd: нужны ID, открытый журнал или уже
связанная сессия. Без привязки свежее событие допускается лишь на короткое
пятисекундное окно до сверки процессов.

Claude Code закрывает журналы между записями. Когда доступен его реестр
`~/.claude/sessions/<pid>.json`, drem берёт оттуда точный session ID, сверяя PID,
платформу и `procStart` с временем запуска процесса из ядра. Поле `status`
реестра не заменяет события задачи. Отсутствующий или повреждённый реестр
не создаёт привязку по одной лишь папке.

Все явно связанные журналы проверяются независимо от возраста, переименования
папки и других сессий в том же cwd. Ограничение в 40 недавних файлов относится
только к поиску неизвестных журналов, а не к проверке сессий с известным ID
или открытым файлом.

Hook и transcript сравниваются по времени семантического события активности,
а не произвольной записи в файл. `token_count` не превращает ожидание в работу;
завершающие события должны победить старый `SessionStart`.
Новый `turn_context` после compaction разрешает следующему реальному
reasoning/tool/commentary-событию открыть продолжение задачи даже без нового
`UserPromptSubmit`. Сама граница не считается работой, а поздний tool output
без неё не может оживить уже завершённую задачу.
Работа, записанная до запуска нынешнего процесса, не переносится на него
при возобновлении старого чата.

Codex хранит `/goal` отдельно от transcript в `~/.codex/goals_1.sqlite`.
`task_complete` и `final_answer` могут завершать отдельный автоматический turn,
не завершая цель. Поэтому `active` для точно связанного `thread_id` удерживает
сессию в состоянии working. `paused`, `blocked`, `usage_limited`,
`budget_limited` и `complete` не удерживают её. Без живого связанного процесса
запись goal сама по себе агентом не считается.

Реестр читается read-only запросом только к `thread_id`, `status` и
`updated_at_ms`; `objective` не выбирается. Текущий набор active-целей хранится
в памяти, а изменения основной SQLite-базы и WAL приходят через те же vnode и
FSEvents-механизмы.

## Стоимость наблюдения

Известные журналы отслеживаются vnode-уведомлениями `DispatchSource`.
FSEvents обнаруживает новые файлы. События объединяются в короткое окно
около 100 мс. Инкрементальный сканер хранит смещение и читает новые байты,
а при первом чтении использует ограниченный хвост.

Watchdog раз в 15 секунд проверяет только известные PID и изменения связанных
журналов, включая ожидающие сессии. Он не запускает `ps`/`lsof`.
Полная сверка допускается на старте, при ручном обновлении, восстановлении
неизвестных сессий и раз в пять минут.
Codex goal registry не опрашивается отдельным таймером: SQLite/WAL будит
монитор только при реальном изменении, а маленький read-only запрос выполняется
внутри уже существующего event batch.
Изменения реестра Claude наблюдаются через FSEvents. Смена одного `status`
при прежней идентичности не запускает `ps`/`lsof`.

UI получает только изменения видимого состояния. Новые timestamps без смены
состояния не перестраивают меню. Для опционального countdown нужен лишь
30-секундный таймер. Иконка не зависит от количества агентов и не анимируется.

## Граница системных эффектов

Обычное удержание использует IOKit assertions, принадлежащие процессу.
Закрытая крышка использует системный `pmset disablesleep` с ограниченным
sudoers-правилом. Эти механизмы отличаются: смерть процесса освобождает assertions,
но сама по себе не возвращает глобальный переключатель. Поэтому `pmset` включает
не основной процесс, а минимальный дочерний guard. Он блокируется на pipe без
таймера и опроса; EOF при штатном выходе, force-quit или краше владельца сначала
возвращает `SleepDisabled 0`, затем завершает guard.

Восстановление сна выполняется при завершении сеанса, исчезновении владельца
guard и запуске после сбоя. Сохранённый флаг фиксируется до завершения
асинхронного включения, чтобы поздний callback или жёстко убитый guard не
оставили блокировку без последующей попытки восстановления.

Завершение agent-сессии не инициирует системный сон. После снятия собственных
assertions и `SleepDisabled 0` управление остаётся у macOS, в том числе для
штатного режима закрытой крышки с внешним дисплеем.

Контроллер яркости не владеет сном. Сначала сохраняется прежнее значение
и UUID панели, затем выполняется затемнение. Ошибка восстановления сохраняет
данные для последующей попытки. Прямые системные эффекты заменяются в обычных
тестах; hardware-проверка включается только явной переменной окружения.

Режим «Вне дома» также не владеет сном. Один `LidStateMonitor` раздаёт событие
закрытия контроллеру яркости и `AwayModeController`. Блокировка вызывается
только на переходе в закрытое состояние, затем подтверждается через текущую
CGSession. Сначала динамически вызывается `SACLockScreenImmediate`; при
отсутствии или неподтверждённом результате используется системное `⌃⌘Q` через
Accessibility. Ни один путь не рисует собственный псевдоэкран блокировки.

`KeepAwakeManager` продолжает владеть IOKit assertions и `SleepDisabled`.
Заблокированный Away-сеанс разрешает сон дисплея, но работающий агент сохраняет
системную assertion. После последнего агента прежний путь освобождения снимает
все ресурсы независимо от состояния экрана и переключателя Away.

## Совместимость имён

Приложение — `drem.app`, Swift package — `Drem`, bundle ID — `local.mrvasil.drem`.
Команды — `dremctl`, `drem-hook`, `drem-selftest`.
`DremMigration` однократно копирует старый домен настроек, не удаляя оригинал
и не перекрывая уже заданные значения drem. Повторный запуск не восстанавливает
устаревшие recovery-флаги. HookStateStore читает также старый каталог состояния,
а установщик заменяет оба поколения обработчиков. Существующее собственное
sudoers-правило Agent Watch признаётся для обновления без повторного запроса пароля.
