# Architecture

[← drem](../README.md)

## Два независимых состояния

Монитор определяет активность сессий. Контроллер сна решает, требуется ли
удержание. Иконка показывает состояние удержания, а счётчик показывает работу
агентов. Эти признаки нельзя объединять в один `isRunning`.

```text
Agent hooks ─────────────┐
Transcript file events ─┤
Codex goal DB events ───┤
Known PID exits ────────┤
15-second watchdog ─────┴─→ LiveActivityEngine ─→ AgentMonitor
                                                    ├─→ menu count and rows
                                                    └─→ KeepAwakeManager
                                                         ├─→ sleep assertions
                                                         ├─→ closed-lid override
                                                         ├─→ LidStateMonitor
                                                         │    ├─→ display brightness
                                                         │    └─→ AwayModeController → macOS lock screen
                                                         └─→ icon + preferences
```

## Идентичность раньше эвристик

Сессия связывается с PID по открытому transcript-файлу или явному session ID.
Для обнаружения журнала остаётся резервное сопоставление по единственной
рабочей папке, только если у процесса нет более точной привязки. Hook не может
заимствовать чужой PID по совпадению cwd: нужны ID, открытый журнал или уже
связанная сессия. Без привязки свежее событие допускается лишь на короткое
пятисекундное окно до сверки процессов.

Claude Code закрывает журналы между записями. Когда доступен его реестр
`~/.claude/sessions/<pid>.json`, drem берёт оттуда точный session ID, сверяя PID,
платформу и `procStart` с временем запуска процесса из ядра. Поле `status`
реестра не заменяет события задачи. Отсутствующий или повреждённый реестр
не создаёт привязку по одной лишь папке.

Все явно связанные журналы проверяются независимо от возраста, переименования
папки и других сессий в том же cwd. Ограничение в 40 недавних файлов относится
только к поиску неизвестных журналов, а не к проверке сессий с известным ID
или открытым файлом.

Hook и transcript сравниваются по времени семантического события активности,
а не произвольной записи в файл. `token_count` не превращает ожидание в работу;
завершающие события должны победить старый `SessionStart`.
Новый `turn_context` после compaction разрешает следующему реальному
reasoning/tool/commentary-событию открыть продолжение задачи даже без нового
`UserPromptSubmit`. Сама граница не считается работой, а поздний tool output
без неё не может оживить уже завершённую задачу.
Работа, записанная до запуска нынешнего процесса, не переносится на него
при возобновлении старого чата.

Codex хранит `/goal` отдельно от transcript в `~/.codex/goals_1.sqlite`.
`task_complete` и `final_answer` могут завершать отдельный автоматический turn,
не завершая цель. Поэтому `active` для точно связанного `thread_id` удерживает
сессию в состоянии working. `paused`, `blocked`, `usage_limited`,
`budget_limited` и `complete` не удерживают её. Без живого связанного процесса
запись goal сама по себе агентом не считается.

Реестр читается read-only запросом только к `thread_id`, `status` и
`updated_at_ms`; `objective` не выбирается. Текущий набор active-целей хранится
в памяти, а изменения основной SQLite-базы и WAL приходят через те же vnode и
FSEvents-механизмы.

## Стоимость наблюдения

Известные журналы отслеживаются vnode-уведомлениями `DispatchSource`.
FSEvents обнаруживает новые файлы. События объединяются в короткое окно
около 100 мс. Инкрементальный сканер хранит смещение и читает новые байты,
а при первом чтении использует ограниченный хвост.

Watchdog раз в 15 секунд проверяет только известные PID и изменения связанных
журналов, включая ожидающие сессии. Он не запускает `ps`/`lsof`.
Полная сверка допускается на старте, при ручном обновлении, восстановлении
неизвестных сессий и раз в пять минут.
Codex goal registry не опрашивается отдельным таймером: SQLite/WAL будит
монитор только при реальном изменении, а маленький read-only запрос выполняется
внутри уже существующего event batch.
Изменения реестра Claude наблюдаются через FSEvents. Смена одного `status`
при прежней идентичности не запускает `ps`/`lsof`.

UI получает только изменения видимого состояния. Новые timestamps без смены
состояния не перестраивают меню. Для опционального countdown нужен лишь
30-секундный таймер. Иконка не зависит от количества агентов и не анимируется.

## Граница системных эффектов

Обычное удержание использует IOKit assertions, принадлежащие процессу.
Закрытая крышка использует системный `pmset disablesleep` с ограниченным
sudoers-правилом. Эти механизмы отличаются: смерть процесса освобождает assertions,
но сама по себе не возвращает глобальный переключатель. Поэтому `pmset` включает
не основной процесс, а минимальный дочерний guard. Он блокируется на pipe без
таймера и опроса; EOF при штатном выходе, force-quit или краше владельца сначала
возвращает `SleepDisabled 0`, затем завершает guard.

Восстановление сна выполняется при завершении сеанса, исчезновении владельца
guard и запуске после сбоя. Сохранённый флаг фиксируется до завершения
асинхронного включения, чтобы поздний callback или жёстко убитый guard не
оставили блокировку без последующей попытки восстановления.

Контроллер яркости не владеет сном. Сначала сохраняется прежнее значение
и UUID панели, затем выполняется затемнение. Ошибка восстановления сохраняет
данные для последующей попытки. Прямые системные эффекты заменяются в обычных
тестах; hardware-проверка включается только явной переменной окружения.

Режим «Вне дома» также не владеет сном. Один `LidStateMonitor` раздаёт событие
закрытия контроллеру яркости и `AwayModeController`. Блокировка вызывается
только на переходе в закрытое состояние, затем подтверждается через текущую
CGSession. Сначала динамически вызывается `SACLockScreenImmediate`; при
отсутствии или неподтверждённом результате используется системное `⌃⌘Q` через
Accessibility. Ни один путь не рисует собственный псевдоэкран блокировки.

`KeepAwakeManager` продолжает владеть IOKit assertions и `SleepDisabled`.
Заблокированный Away-сеанс разрешает сон дисплея, но работающий агент сохраняет
системную assertion. После последнего агента прежний путь освобождения снимает
все ресурсы независимо от состояния экрана и переключателя Away.

## Совместимость имён

Приложение — `drem.app`, Swift package — `Drem`, bundle ID — `local.mrvasil.drem`.
Команды — `dremctl`, `drem-hook`, `drem-selftest`.
`DremMigration` однократно копирует старый домен настроек, не удаляя оригинал
и не перекрывая уже заданные значения drem. Повторный запуск не восстанавливает
устаревшие recovery-флаги. HookStateStore читает также старый каталог состояния,
а установщик заменяет оба поколения обработчиков. Существующее собственное
sudoers-правило Agent Watch признаётся для обновления без повторного запроса пароля.
